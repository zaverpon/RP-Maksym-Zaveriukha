# Centralized Process Communication via Shared Memory

A C project implementing and benchmarking centralized inter-process communication using POSIX shared memory.

The project explores communication between multiple processes through a central router and measures the performance of the communication layer under different workloads.

## Project include 

* Inter-process communication in C
* POSIX shared memory
* Memory mapping with `mmap`
* Process creation with `fork`
* Process synchronization using semaphores
* Multithreading with `pthread`
* Centralized message routing
* Performance benchmarking
* Latency and throughput measurements

## Communication Layer

The communication API is exposed through `com.h` and provides operations for:

```c
com_initialize(...)
com_prepare_send_buffer(...)
com_send(...)
com_recv(...)
com_mcast(...)
com_finalize(...)
```

Processes communicate through shared-memory segments while synchronization primitives coordinate access to messages and shared state.

A dedicated router process handles message metadata and forwards it to the destination process.

## Benchmark 1 — All-to-All Communication

`rpBenchmark1` measures communication where every process sends messages to every other process.

Each process uses:

* one sender thread;
* one receiver thread.

The benchmark measures:

* total execution time;
* average cycle time;
* average message latency;
* throughput in MiB/s.

### Build

```bash
cd rpBenchmark1
make main
```

### Run

```bash
./main <num_processes> <message_size> <repeat_count>
```

Example:

```bash
./main 4 1024 10000
```

Where:

* `num_processes` — number of communicating processes;
* `message_size` — message size in bytes;
* `repeat_count` — number of communication cycles.

## Benchmark 2 — Distributed Request/Response Workload

`rpBenchmark2` simulates a distributed database-like request/response workload.

Processes exchange requests and responses concurrently while the benchmark collects performance statistics.

The benchmark measures:

* mean response latency;
* latency standard deviation;
* requests per second;
* response throughput in MiB/s;
* total execution time.

### Build

```bash
cd rpBenchmark2
make main
```

### Run

```bash
./main <num_processes> <requests_per_process> <response_size>
```

Example:

```bash
./main 3 10000 1024
```

Where:

* `num_processes` — number of processes;
* `requests_per_process` — number of requests generated by each process;
* `response_size` — response payload size in bytes.

## Purpose

The project was created to explore low-level process communication, synchronization and performance characteristics of shared-memory-based IPC.

It also demonstrates benchmarking of concurrent workloads using different message and response sizes.
